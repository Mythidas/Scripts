# M365 toolkit

Multi-tenant Microsoft 365 management over GDAP. Run one script (or command) against one tenant, a customer, a group, or all tenants.

## Layout

| Path | What |
|---|---|
| `Toolkit/` | `CSToolkit` module: auth, tenant registry, per-tenant runner, Graph client, result/export helpers |
| `Config/tenants.csv` | Tenant registry (gitignored, generated by `Sync-CSTenantRegistry`). Format: `Config/tenants.example.csv` |
| `Config/Profiles/` | Baseline / Standard rule definitions (health check, coming next) |
| `Data/` | Reports and run logs (gitignored) |
| `Tests/` | Pester tests: `Invoke-Pester ./Tests` |
| `Templates/` | Starting point for new tenant scripts |
| `Test-TenantAccess.ps1` | Per-tenant probe of what your GDAP sign-in can read |

## Workflow

```powershell
Import-Module ./Toolkit/CSToolkit.psd1
Connect-CSPartner                 # once per pwsh session: browser sign-in (MFA), token kept in memory only
Sync-CSTenantRegistry -WhatIf     # then without -WhatIf; afterwards fill Customer / Group / Profile / Features in tenants.csv
.\Test-TenantAccess.ps1           # what can we read in each tenant?

Get-CSTenant -Customer 'Acme*'                     # select
Get-CSTenant -Group Dental -Feature Intune | Invoke-CSForEachTenant { param($t) ... }
```

Run scripts from the same pwsh window so the partner sign-in is reused; each script signs in itself if there is no session.

## Registry columns

`TenantId, DefaultDomain, DisplayName` and `GdapStatus` are synced from GDAP. You own `Customer` (one customer can have several tenants),
`Group` (semicolon-separated tags), `Profile` (Baseline / Standard), `Features` (semicolon-separated: Intune, EntraP2), `Enabled` and `Notes`;
sync never overwrites them. Tenants that disappear from GDAP are kept and marked `Missing`.

## How a multi-tenant run works

1. `Invoke-CSForEachTenant` mints a delegated token per tenant from the partner session (refresh-token redemption, no extra prompts).
2. Each tenant runs in its own process, so tenants cannot interfere with each other. A failure in one never stops the rest.
3. Inside the script block `Invoke-CSGraph` and `New-CSResult` already know the tenant. Return `New-CSResult` rows.
4. `Expand-CSTenantRun` turns failed tenants into `Error` rows; `Export-CSResult` writes CSV + JSON; `Get-CSResultSummary` rolls up per tenant.

Result status: `Pass | Fail | Warn | NA | Error`. `Error` means "could not evaluate" (no access, not licensed) and is never counted as `Fail`.

## Script standard

`#Requires -Version 7.0`, comment-based help, `[CmdletBinding(SupportsShouldProcess)]` with real `-WhatIf` (not a custom switch), the same four tenant
filters, progress for long loops, idempotent re-runs, a log/rollback file for any change, results through `New-CSResult`. See `Templates/Script.template.ps1`.
Lint: `Invoke-ScriptAnalyzer -Path . -Recurse -Settings ./PSScriptAnalyzerSettings.psd1`.
